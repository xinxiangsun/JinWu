已知限制与使用检查
==================

本页记录已知仍会影响使用的问题；文档修正不会自动修复底层算法。
本地验证与远端 CI 覆盖应分别核查。

GBM 背景残差与曝光近似
----------------------

0.2.4 已修复 GTI 覆盖、同 TIME 事件丢失及全能道死时间计算。
候选阶数的留出打分使用 Poisson deviance；独立的残差门禁仍对
``(N-mu)/sqrt(max(N,1))`` 使用正态参考阈值。条件 Poisson
模拟提示该门禁可能存在标定误报；背景时间趋势仍需独立诊断，不能因此宣称背景正确。
下一步应在模拟中完整重拟合并重选阶数，校准时间趋势及拟合优度，检查离源窗口
的预测覆盖。本次未实现此修正，也未放宽现有阈值；失败继续记为 ``needs_review``。

背景网格的末箱延伸策略及 GDT ``get_exposure(scale=True)`` 对相交箱曝光的
整体比例近似仍保留。Triggered TTE、跨 GTI 缺口、新响应及通量/上限/FAR
完整流程仍需针对实际数据验收。坐标/姿态、旋转区域、缓存和 host 星表来源
也需在相应使用场景中核查。

WXT 外部工具与文档构建
----------------------

0.2.4 已修复跨阶段改写 PHA 导致的缓存失效。真实 XSELECT 验证中，产物写出
及退出交互后仍有 SIGABRT/SIGSEGV；既有包装器在产物核验通过时允许这种
退出清理异常。另有长输出路径下的退出超时，根因尚未确定。产物/缓存检查通过
不等于原生工具运行健康；WXT slew、时变响应和新拟合不在本轮验收范围。

本地全量严格 Sphinx 构建仍有 5 条既有警告：时标 docstring 1 条、
Swift autodoc 可选依赖导入 4 条。新增页面的检查不能替代全量构建通过。

发行准备
--------

当前源码发行元数据为 0.3.1；各包实际上传状态以 PyPI 为准，不能由 tag 或构建成功推断。
公开文件边界检查和产物收集修正不构成新的科学验收。
此前 Rust wheel 的本地构建、安装与冒烟检查限于 Linux x86_64 的
``jinwurs-0.3.0-cp311-abi3-manylinux_2_34_x86_64``；不代表 0.3.1 或其他平台已验证。
conda 配方仍使用占位 SHA256，提交前必须核对最终发布的 sdist；
Rust 配方还需要可用的 sdist，不能直接使用 wheel 替代。

光变拟合状态
------------

0.2.2 已修正 ``LightcurveFitter.success``：后端未收敛或模型/统计量非有限时返回 False，
且不提供有效参数误差。零值、负值或非有限 measurement error 会抛出 ValueError；
调用方须提供有统计依据的误差或显式筛选数据。收敛仍不能替代残差、边界与模型检验。

PHA 通道能量
------------

PHA 不一定包含 EBOUNDS。请从匹配的 RMF/RSP 获取通道定义，
核查通道编号一致；见 :doc:`quickstart`。ARF 的能量 bin 不能代替 EBOUNDS。

Swift Burst Analyser ECF 表
---------------------------

0.2.2 已修正 ``read_burst_analyser_dat`` 的 14 列 ``XRTBand`` 表：
ECF 读取第 12 列，计数率由 flux/ECF 得到；计数率统计误差使用未包含 ECF
不确定度的 flux 误差列。遗留独立脚本的列定义仍须对照原始表头核验。
原始格式见 `UKSSDC GRB 数据说明 <https://www.swift.ac.uk/API/ukssdc/data/GRB.md>`_。

红移与模型语义
--------------

遗留 ``RedshiftExtrapolator`` 示例不适合作为通用红移算法依据。
``powerlaw`` 和 ``zpowerlw`` 的归一化变换不同；吸收红移、cosmology 和能段
必须随模型结构处理。通用变换的设计说明见 :doc:`lf_redshift_transform`。
当前模拟接口的计算结果仍需逐模型验证，尤其不能把未验证的高红移触发边界当测量。

计数统计与未探测
----------------

SNR 的背景已知分支保留移植实现的严格尾概率语义；小计数时与其他尾概率约定可能不同，
见 :doc:`usage/significance`。Gaussian 净计数率上限需要相应误差/协方差，
GBM/BAT 固定模板 limit 需要响应、背景与校准质量。
搜索 ``loglr``、程序返回成功或文件存在均不足以构成显著检测。

数据对齐与环境
--------------

0.2.2 的 ``netdata`` 要求相同 TIMEZERO 和严格相合的 bin；细背景 bin 可在完整覆盖
且不跨源 bin 边界时聚合。错位或不完整覆盖会抛出 ValueError。调用前仍须核对时间系统与 GTI。
网络星表、UKSSDC 与 GraceDB 服务可能不可用；配置本地缓存并保留查询来源。
部分 API 页仅展示可选后端的签名，运行前仍需安装真实依赖。
